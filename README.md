# スプラッシュ・アイル — ヒカリ島の大そうじ

水を噴射して島の汚れ（スミ）を洗い流し、ホバーで飛びまわって 14 個の「ヒカリ石」を集める、ブラウザで遊べる 3D アクションです。
拠点の町から 3 つのエリアへ出かけ、エリアごとに 3 つのステージに挑みます。
南国の島を水の力で掃除してまわる往年の 3D アクションへのオマージュですが、キャラクター・世界観・素材はすべてオリジナルです。

- 描画: Three.js（WebGL2）。HDR レンダリング、ソフトシャドウ、MSAA、ブルーム、海面のリアルタイム反射
- アセット: 地形・建物・キャラクター・海・空・効果音・BGM まで **すべてコードで生成**（画像・モデル・音声ファイルなし）
- インフラ: Cloudflare Workers（静的配信 + API）と D1（セーブ・ランキング・セッション）
- 認証: Google ログイン（OAuth 2.0 認可コードフロー + PKCE / OpenID Connect）。ログインなしでもゲストで遊べます

## エリアとステージ

ヒカリ石は全部で 14 個（町に 5 個、3 エリア × 3 ステージで 9 個）。

| エリア | ステージ 1 | ステージ 2 | ステージ 3 |
|---|---|---|---|
| ヒカリ島の町（拠点） | 広場のスミ掃除／灯台のてっぺん／ヒトデ 8 つ／沖の浮きブロック／スミボウ退治（順不同の 5 個） | | |
| ゆけむり山（温泉火山・夕方） | 火口のまんなかへ | 温泉街のスミを洗い流す | 山にちらばるヒトデを 8 つ |
| サンゴ入り江（難破船の環礁・真昼） | 難破船のマストのてっぺんへ | スミボウたいじ（大きいのが 1 匹いる） | サンゴの上のヒトデを 8 つ |
| そよかぜ台地（吊り橋と気球・朝） | いちばん高い台地へ | 台地の村のスミを洗い流す | 空にちらばるヒトデを 8 つ |

エリアの行き来:

1. ヒカリ石が規定数（0 個・3 個・5 個）たまると、町の建物（時計塔・港の倉庫・丘のふもとの石の門）がスミのかたまりに覆われる
2. 水をかけて洗い流すと、壁に入口のしるしが現れる
3. しるしに飛びこむとステージ選択。ステージは前のものをクリアすると次が選べる（クリア済みも再挑戦可）
4. ステージでヒカリ石を取ると町へ戻る。ポーズ画面の「町へもどる」で途中で帰ることもできる

仕掛け: 間欠泉（噴き上がるときに乗ると上の段へ打ち上げられる）、動く足場、気球のゴンドラ、板の吊り橋、しずく玉（水が満タンになる）。

## ローカルで動かす

Node.js 22 以上が必要です。

```bash
npm install

# ゲームだけを素早く試す（API なし・ゲストモード）
npm run dev                # http://localhost:5173

# Worker と D1 も含めて本番と同じ構成で試す
cp .dev.vars.example .dev.vars    # Google の値を入れる（未設定でもゲストでは遊べます）
npm run db:migrate:local
npm run preview            # ビルドして http://localhost:8787 で起動
```

## Cloudflare へデプロイする

画面つきの細かい手順は GitHub の Issue（`manual` ラベル）にあります。ここは要点だけです。

1. **D1 データベースを作る**

   ```bash
   npx wrangler login
   npx wrangler d1 create splash-isle --location apac
   ```

   「設定ファイルに追加しますか」と聞かれたら **No** を選び、表示された `database_id` を `wrangler.jsonc` の `d1_databases[0].database_id` に貼り付けます。

2. **テーブルを作る**

   ```bash
   npm run db:migrate     # 本番の D1 にマイグレーションを適用
   ```

3. **Google の OAuth クライアントを作る**（[Google Auth Platform](https://console.cloud.google.com/auth/overview) → クライアント → クライアントを作成）

   - 種類: 「ウェブ アプリケーション」
   - 承認済みのリダイレクト URI:
     - `https://<あなたのドメイン>/api/auth/callback`
     - `http://localhost:8787/api/auth/callback`（ローカル確認用）
   - スコープは `openid` と `profile` だけで足ります（メールアドレスは取得しません）
   - クライアント シークレットは作成直後の画面でしか表示されません。その場で控えてください

4. **クライアント ID とシークレットを設定してデプロイ**

   - `wrangler.jsonc` の `vars.GOOGLE_CLIENT_ID` にクライアント ID を書く（公開してよい値）
   - シークレットは設定ファイルに書かず、`.secrets.env`（Git 管理外）に 1 行で書く

     ```
     GOOGLE_CLIENT_SECRET=ここにシークレット
     ```

   ```bash
   npm run deploy:first   # 初回だけ。ビルド → シークレットつきで wrangler deploy
   ```

   `wrangler.jsonc` で `GOOGLE_CLIENT_SECRET` を必須にしているため、初回はシークレットを一緒に送らないとデプロイが止まります。
   2 回目以降は `npm run deploy` だけで済みます。シークレットを入れ替えるときは `npx wrangler secret put GOOGLE_CLIENT_SECRET` を使います。

   独自ドメインを使う場合は `wrangler.jsonc` に `routes`（`custom_domain: true`）を追加し、手順 3 のリダイレクト URI も合わせます。

## 画質と解像度の考え方

- 内部解像度は実測フレームレートに合わせて自動で上下しますが、**どの設定・どの端末でも 1280×720 相当（約 92 万画素）を下回りません**。ゲームキューブの 640×480（約 31 万画素）の約 3 倍です。ウィンドウが小さい場合はスーパーサンプリングになります（`src/engine/renderer.ts` の `MIN_PIXELS`）。
- 品質は 3 段階。「自動」では GPU 名から初期値を決め、解像度の下限でも重いときだけ段階を下げます。

  | | 低 | 中 | 高 |
  |---|---|---|---|
  | 解像度の上限（画面比） | ×1 | ×1.5 | ×2 |
  | アンチエイリアス | MSAA ×2 | MSAA ×4 | MSAA ×4 |
  | 影 | 1024 | 2048 | 4096 |
  | ブルーム | なし | あり | あり |
  | 海面の反射 | 空のみ | 空のみ | 島や足場も映る |
  | 草むら・花 | なし | あり | あり |

- 軽さのための工夫: 建物や小物は頂点カラーで数個のメッシュに統合、植物はインスタンシング、パーティクルは 1 ドローコール、
  水深は深度バッファを読まずに地形の高さテクスチャから計算、当たり判定は自前の軽量実装（物理エンジンなし）。
  転送量は JS 約 220KB（gzip）のみで、画像・モデル・音声のダウンロードはありません。

## プロジェクト構成

```
index.html            画面（HUD・メニュー）
src/
  main.ts             起動、ゲーム進行、メインループ
  styles.css          UI のスタイル
  engine/             renderer（品質・動的解像度）, input, audio（効果音と BGM の合成）, noise
  world/              terrain（地形の差し替えとシェーダー）, water, sky, props, goop（スミ）, colliders
    area.ts           エリア共通の土台（家・橋・足場・間欠泉・植物などの部品）
    areas/town.ts     拠点の町（通り・時計塔・港・灯台・3つの入口）
    areas/stages.ts   ゆけむり山・サンゴ入り江・そよかぜ台地（各3ステージ）
  game/               player, camera, particles, collectibles, enemies, npc, portals（入口）, bird（キャラクター）, hud, state（セーブ）
  net/api.ts          API クライアント
worker/               Cloudflare Worker（index: ルーティング, auth: Google ログイン, session, save, http）
migrations/           D1 のスキーマ
public/_headers       セキュリティヘッダー（CSP など）とキャッシュ設定
scripts/              開発用の自動テスト
```

## セキュリティとデータについて

- 保存するのは Google アカウントの識別子（`sub`）・表示名・アイコン URL と、セーブデータだけです。メールアドレスは取得しません。
- セッションは HttpOnly / Secure / SameSite=Lax の Cookie（`__Host-` 接頭辞）で、DB にはトークンの SHA-256 ハッシュだけを保存します。
- ID トークンは Google の公開鍵で署名を検証し、発行者・宛先・期限・nonce を確認します。state と PKCE も使っています。
- 状態を変える API は同一オリジンからのリクエストだけ受け付けます。
- ランキングは、14 個すべて集めたときのタイムで競います。クリアタイムはクライアントからの申告です。ランキングを厳密にしたい場合は、サーバー側での検証（リプレイ検証など）の追加が必要です。
